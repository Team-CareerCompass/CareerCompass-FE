## 1. 알림 목록

### 화면 구조

```
[← ]  알림                                   [ 모두 읽음 ]   ← TopAppBar (action)
─────────────────────────────────────────────
 ●  [아이콘]  제목 한 줄                        3분 전
             본문 두 줄까지, 넘치면 말줄임…
─────────────────────────────────────────────
    [아이콘]  제목 한 줄                        어제
             본문…
─────────────────────────────────────────────
```

- 한 줄은 **읽음 점(●) · 아이콘 · 제목 · 본문 · 받은 시각** 다섯 조각이다.
- **읽지 않은 것만 왼쪽에 점**을 찍는다. 배지 구현은 피드가 쓰는 것과 같은 한 벌을 쓴다
  (FE [#170](https://github.com/Team-CareerCompass/CareerCompass-FE/issues/170) 에서 두 벌로 갈렸던 것을 합쳤다 — 세 번째 벌을 만들지 않는다).
- 시각은 상대 표기(`3분 전`·`어제`·`3일 전`), 7일이 넘으면 절대 날짜(`9월 4일`).
- 줄 전체가 탭 대상이다. 탭하면 읽음 처리 + 딥링크 이동. **최소 높이 48dp**, 큰 글꼴(fontScale 2.0)에서 높이는 늘어나야 하고 잘리면 안 된다.

### 종류 넷을 한 줄에서 가르는 것

색이 아니라 **아이콘과 제목 문구**로 가른다(색만으로 나르면 색각 이상에서 구별되지 않는다).

| 종류 | API 키 | 아이콘 | 제목 | 본문 | 탭하면 |
| --- | --- | --- | --- | --- | --- |
| 신규 공고 | `newPosting` | `Add` | `새 공고 3건` | `{게시판 이름}에 새 공고가 올라왔어요` | 그 게시판으로 좁힌 피드 |
| 마감 임박 | `dueSoon` | `Notifications` | `마감 D-1` | `{공고 제목} 마감이 하루 남았어요` | 그 공고 상세 |
| 수집 오류 | `boardError` | `Close` | `수집이 멈췄어요` | `{게시판 이름}에서 3회 연속 실패했어요` | 게시판 관리(그 게시판 카드) |
| 주간 리포트 | `weeklyReport` | `Check` | `이번 주 요약` | `새 공고 {n}건 · 마감 임박 {m}건` | 피드 |

> **주간 리포트의 발송 조건은 아직 정해져 있지 않다.** 명세서 F2-4 표에는 없고 API_SPEC 설정 스키마에만 키가 있다.
> 설정 화면에는 넣되, 서버가 실제로 보내기 전까지 목록에는 나타나지 않는다.

### 상태

| 상태 | 화면 |
| --- | --- |
| 로딩 | 목록 자리에 스켈레톤 3줄 |
| 빈 목록 | `CareerCompassStateView` — 「아직 받은 알림이 없어요 / 게시판을 등록하면 새 공고를 알려드려요」 + `게시판 등록` 버튼 |
| 조회 실패 | 엣지 상태 「연결 실패」 + `다시 시도` |
| 알림 권한 꺼짐 | 목록 **위에** 띠 하나 — 「알림이 꺼져 있어요 · 켜기」. 목록은 그대로 보인다(받은 알림은 이미 있다) |
| 모두 읽음 직후 | 점이 모두 사라지고 스낵바 「모두 읽음으로 표시했어요」 |

- `모두 읽음` 은 **읽지 않은 것이 하나라도 있을 때만** 활성이다. 누르면 되돌릴 수 없으니 눌린 뒤 스낵바로 알린다.
- 페이징은 피드와 같은 커서 방식. `GET /notifications` 의 응답 스키마가 아직 API_SPEC 에 없다 —
  **목록 화면을 만들기 전에 서버와 맞춰야 한다**(항목 id·종류·제목·본문·받은 시각·읽음 여부·딥링크 대상).

## 2. 알림 설정

`GET /notifications/settings` / `PUT` 의 스키마를 그대로 화면으로 옮긴다.

```
[← ]  알림 설정
─────────────────────────────────────────────
 알림 받기                                     ← 시스템 권한 안내 (꺼져 있을 때만)
─────────────────────────────────────────────
 종류
   새 공고                                [ON ]
   마감 임박                               [ON ]
   수집 오류                               [ON ]
   주간 리포트                              [OFF]
─────────────────────────────────────────────
 시간
   방해 금지                               [ON ]
     23:00  →  08:00                       ← ON 일 때만 보인다
   주말에는 받지 않기                        [OFF]
─────────────────────────────────────────────
 게시판별                              12 / 20
   [ 게시판 검색 ]                          ← 8개를 넘으면 나타난다
   컴퓨터공학과 공지                        [ON ]
   … (더 보기 8개)                          ← 처음엔 8개만, 나머지는 접는다
─────────────────────────────────────────────
```

- **방해 금지 시간대** — 시작·종료를 각각 시각 선택기로. `23:00 → 08:00` 처럼 **자정을 넘는 구간을 허용**한다
  (넘는 것이 기본 사용례다). 시작과 종료가 같으면 「하루 종일 받지 않음」이라는 뜻이 되므로 저장을 막고 문구로 알린다.
- **게시판별 ON/OFF** — 게시판은 최대 20개다. 20개를 한 화면에 세로로 늘어놓으면 시간 설정이 화면 밖으로 밀려난다.
  그래서 **처음 8개만 펼치고 나머지는 「더 보기」로 접는다.** 8개를 넘으면 검색칸이 함께 나타난다.
  헤더 오른쪽에 `켜진 수 / 전체 수` 를 적어 접혀 있어도 상태를 알 수 있게 한다.
- **삭제된 게시판**이 설정에 남아 있으면 목록에 「사라진 게시판」으로 보이고 한 번에 지울 수 있어야 한다
  (피드 필터에서 같은 함정을 겪었다 — FE [#155](https://github.com/Team-CareerCompass/CareerCompass-FE/issues/155)).
- 스위치를 누르면 **낙관적으로 켜고 PUT 실패 시 되돌린다.** 되돌릴 때는 스낵바로 알린다. 저장 버튼은 두지 않는다.
- 종류 스위치를 모두 끄면 「알림을 받지 않게 됩니다」를 한 줄로 알린다. 막지는 않는다.

### 시스템 권한이 꺼져 있을 때

Android 13+ 는 `POST_NOTIFICATIONS` 런타임 권한이다. 꺼져 있으면 **이 화면의 스위치를 다 켜도 알림이 오지 않는다.**

- 화면 맨 위에 안내 띠 — 「휴대폰 설정에서 알림이 꺼져 있어요 · 설정 열기」. 누르면 앱 알림 설정으로 보낸다.
- 그 아래 스위치들은 **끄지 않는다**(서버 설정은 그대로 유효하다). 대신 흐리게 그려 지금은 효력이 없음을 보인다.
- Figma 09 Edge Cases 의 「알림 권한이 꺼져 있어요」 화면과 이어진다. 전면 화면이 아니라 **띠**인 이유는,
  받은 알림 목록과 서버 설정은 권한과 무관하게 여전히 볼 수 있기 때문이다.

## 3. 다크 모드

두 화면 모두 `core:ui` 의 의미 색 역할만 쓴다(`surface`·`onSurface`·`mutedContent`·`outline`·`primary`).
팔레트 값을 직접 쓰지 않으면 다크는 저절로 따라온다. 13 페이지의 06·07 은 07 Dark Mode 의 값(#0a0a0a 바탕,
#171717 카드, #262626 선)으로 그린 대비 확인용 시안이고, 구현이 따로 맞출 값은 없다.
다만 읽지 않음 점과 「사라진 게시판」 태그는 대비가 얕아지기 쉬우니 대비 검증 대상에 넣는다
(FE [#205](https://github.com/Team-CareerCompass/CareerCompass-FE/issues/205)).
