# Play 스토어 등록 정보

내부 테스트 릴리스를 만들려면 자산과 앱 콘텐츠 선언이 먼저 채워져 있어야 한다. 절차와 순서는 [`docs/play-release.md`](../play-release.md) 에 있고, 이 문서는 거기 붙일 내용이다.

## 자산

| 항목 | 규격 | 파일 | 상태 |
|---|---|---|---|
| 앱 아이콘 | 512×512 PNG | [`assets/icon-512.png`](assets/icon-512.png) | 있음 |
| 피처 그래픽 | 1024×500 PNG | [`assets/feature-graphic.png`](assets/feature-graphic.png) | 있음 |
| 스크린샷 | 폰 2~8장, 16:9 또는 9:16 | 없음 | 화면이 더 나온 뒤 |

두 이미지는 같은 폴더의 SVG 가 원본이다. 색과 도형은 런처 아이콘(`app/src/main/res/drawable/ic_launcher_foreground.xml`)과 같은 나침반 마크이고 브랜드 에메랄드(`Brand500` `#10B981`)를 쓴다. 고칠 일이 생기면 SVG 를 고치고 다시 뽑는다.

```bash
cd docs/store/assets
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu --hide-scrollbars \
  --screenshot=icon-512.png --window-size=512,512 "file://$PWD/icon-512.svg"
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu --hide-scrollbars \
  --screenshot=feature-graphic.png --window-size=1024,500 "file://$PWD/feature-graphic.svg"
```

### 스크린샷을 아직 찍지 않은 이유

스토어 스크린샷은 기능 나열이 아니라 이야기 순서로 고른다. 공고를 모아서, 적합도를 보고, 지원서를 만든다는 순서다. 그런데 그 이야기의 뒷부분인 지원서 화면이 아직 없다(#182 이후). 지금 찍으면 앞의 절반만 보여 주는 스크린샷이 되고, 화면이 나오면 어차피 다시 찍는다.

찍을 때의 목록은 이렇게 잡는다.

1. 메인 피드. 여러 게시판에서 모인 공고 목록
2. 게시판 등록. URL 하나로 공고가 들어오기 시작하는 자리
3. 공고 상세의 적합도 4축
4. 적합도 필터로 걸러 본 피드
5. 지원서 초안 생성
6. 지원서 에디터의 항목별 편집
7. For You 추천
8. 알림 설정

## 스토어 등록 정보

### 앱 이름

CareerCompass

### 짧은 설명 (80자 이내)

> 공고를 모아 적합도를 분석하고 자기소개서 초안까지 만들어 주는 취업 준비 앱 (46자)

### 전체 설명

> 흩어진 공고를 한곳에 모읍니다.
>
> 학교 공지, 학과 게시판, 채용 사이트를 매일 들어가 확인하지 않아도 됩니다. 보고 싶은 게시판 주소를 등록하면 CareerCompass 가 주기적으로 확인해 새 공고를 가져옵니다. 장학금, 공모전, 채용 공고를 한 화면에서 봅니다.
>
> 나에게 맞는 공고인지 먼저 알려 줍니다.
>
> 프로필과 경험을 한 번 입력해 두면 공고마다 적합도를 4개 축으로 나눠 보여 줍니다. 무엇을 충족했고 무엇이 모자란지 근거와 함께 보여 주기 때문에, 지원할지 말지를 공고 본문을 다 읽기 전에 판단할 수 있습니다.
>
> 자기소개서 초안을 대신 씁니다.
>
> 등록해 둔 경험 카드를 근거로 문항별 초안을 만듭니다. 마음에 들지 않는 문항만 다시 생성하고, 이전 버전으로 되돌릴 수 있습니다. 글자 수는 문항 제한에 맞춰 셉니다.
>
> 마감을 놓치지 않게 알립니다.
>
> 새 공고, 마감 3일 전과 하루 전, 수집 오류를 알림으로 받습니다. 알림은 유형별로 끄고 켤 수 있고 방해 금지 시간을 정할 수 있습니다.
>
> 건국대학교 졸업 프로젝트로 만들고 있습니다.

- 태그: 취업, 채용, 장학금, 공모전, 자기소개서

- 웹사이트: 개인정보처리방침을 올린 페이지. 게시처와 주소는 [`privacy-policy-hosting.md`](privacy-policy-hosting.md)

## 앱 콘텐츠 선언

Play Console 의 정책 및 프로그램 → 앱 콘텐츠에서 채운다. 하나라도 비면 내부 테스트 릴리스를 만들 수 없다.

| 선언 | 답 | 근거 |
|---|---|---|
| 개인정보처리방침 URL | 게시 후 채운다 | [`privacy-policy.md`](privacy-policy.md) 를 공개 URL 로 올린다. 게시처와 절차는 [`privacy-policy-hosting.md`](privacy-policy-hosting.md) |
| 광고 | 없음 | 광고 SDK 를 넣지 않았고 매니페스트가 광고 ID 권한을 제거한다 |
| 앱 접근 권한 | 전체 기능에 로그인 필요 | 심사용 계정과 절차를 함께 적는다 |
| 콘텐츠 등급 | 설문 응답 필요 | 사용자 생성 콘텐츠는 본인만 보는 자기소개서다. 공유·소통 기능이 없다 |
| 타겟층 | 만 18세 이상 | 대학생 취업 준비가 대상이고 아동 대상 기능이 없다 |
| 데이터 보안 | 아래 표 | |

### 데이터 보안 답안

| 데이터 | 수집 | 공유 | 목적 | 선택 여부 |
|---|---|---|---|---|
| 이메일 주소 | 예 | 아니오 | 계정 식별 | 필수 |
| 이름 | 예 | 아니오 | 계정 표시 | 필수 |
| 학교·전공·학년·희망 직무·관심 태그 | 예 | 아니오 | 적합도 분석과 추천 | 필수 |
| 경험 카드 | 예 | 예 | 적합도 분석, 자기소개서 초안 생성 | 필수 |
| 과거 지원서 파일과 본문 | 예 | 예 | 문체 참고와 항목 분류 | 선택 |
| 생성·저장한 지원서 | 예 | 예 | 사용자가 다시 열어 편집 | 필수 |
| 앱 활동(읽은 공고·북마크) | 예 | 아니오 | 피드 표시와 추천 | 필수 |
| 크래시 로그·진단 | 예 | 예 | 오류 수정(Crashlytics) | 필수 |
| 기기 알림 토큰 | 예 | 아니오 | 알림 발송 | 선택 |

공유로 표시한 항목은 서버가 LLM API 로 보내는 것이다. 전송 범위와 마스킹은 [BE #48](https://github.com/Team-CareerCompass/CareerCompass-BE/issues/48) 이 정하고, 그 결정이 확정되면 이 표와 개인정보처리방침을 함께 고친다. 확정 전에는 스토어 선언을 제출하지 않는다. 선언과 실제가 다르면 정책 위반이다.

전송 중 암호화는 예다. 앱은 평문 HTTP 를 차단한다. 저장 시 암호화 여부는 [#271](https://github.com/Team-CareerCompass/CareerCompass-FE/issues/271) 의 결정을 따른다. 데이터 삭제 요청 경로는 개인정보처리방침에 적은 문의처다.
